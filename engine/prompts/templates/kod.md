Task type: coding / software. A strong coding prompt usually covers, as far as the request supports it:
- The goal in one or two sentences: what should exist or change when the work is done.
- Tech stack, language and versions, framework, environment (only what the user stated or clearly implied).
- Relevant existing code, files, APIs or data structures, and patterns to follow.
- Functional requirements, then non-functional ones (performance, security, style) only if requested.
- Constraints: what must not change, libraries allowed or forbidden, scope limits.
- Expected output: full file, diff, function only, explanation or not, tests or not.
- How to verify: example input/output, test cases, commands.
Missing but essential facts (e.g. language when it matters) become {$PLACEHOLDER} or an assumption, never invented.
